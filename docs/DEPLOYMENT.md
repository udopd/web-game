# Запуск и эксплуатация

`docker-compose.yml` содержит PostgreSQL 17, SeaweedFS S3 и профиль `full` с приложением. Образы PostgreSQL, S3 и Node закреплены digest. Приложение работает от пользователя `node`, перед стартом применяет миграции и идемпотентный seed. Секреты не копируются в Docker build context. URL базы для генерации Prisma на этапе build — локальное фиктивное значение; соединение при генерации не выполняется.

## Окружение

| Переменная | Назначение |
|---|---|
| NODE_ENV | development для локального HTTP; production требует HTTPS APP_ORIGIN |
| HOST / PORT | Адрес прослушивания; локально 127.0.0.1:3100, в контейнере 0.0.0.0:3100 |
| APP_ORIGIN | Единственный разрешённый Origin, включая схему и порт |
| ADMIN_EDITOR_TOKEN | Случайный секрет администратора не короче 40 символов |
| EDITOR_SESSION_TTL_SECONDS | Абсолютный срок административной сессии, 28800 |
| EDITOR_SESSION_IDLE_SECONDS | Неактивность административной сессии, 1800 |
| DATABASE_URL / POSTGRES_PASSWORD | PostgreSQL; Compose подменяет hostname на postgres |
| S3_ENDPOINT / S3_REGION / S3_BUCKET | S3 endpoint, регион и приватный bucket |
| S3_ACCESS_KEY / S3_SECRET_KEY | Доступ сервера к S3 |

Порт PostgreSQL опубликован только на loopback 5437; S3 — 9010; приложение — 3100. Для публичного сервера нужен reverse proxy с TLS и WebSocket upgrade к 3100. Установите NODE_ENV=production и точный HTTPS APP_ORIGIN, ограничьте доступ к БД/S3, настройте резервное копирование обоих volumes. Public bucket policy не нужна: опубликованные файлы выдаёт сервер по manifest. Внешний домен, TLS и облачный deploy здесь не настроены и не проверены.

## Диагностика

`GET /health` проверяет реальный запрос PostgreSQL и доступность S3. `docker compose ps` показывает healthchecks. `docker compose logs --tail 100 app` показывает миграции, seed и ошибки сервера; не публикуйте `.env` или полную конфигурацию Compose с подставленными секретами.

При обновлении остановите приём новых подключений на proxy, корректно завершите текущий процесс, примените миграции и запустите новую сборку. Запуск двух RoomManager на одной БД не поддерживается: распределённые leases отсутствуют. Активные комнаты восстанавливаются из snapshots и продолжают симуляцию, когда появляется подключённый игрок.

Смена ADMIN_EDITOR_TOKEN инвалидирует существующие editor sessions после рестарта. Обычный reset прогресса игрока сохраняет UID, lifetime statistics, настройки и permanent unlocks. Удаление Docker volumes уничтожает данные; для обновления оно не требуется.

Архивы pack и связанные ассеты необходимо сохранять, пока существуют привязанные к ним забеги. Rollback в редакторе изменяет активный указатель, а не содержимое версии. Автоматический garbage collection архивов, удалённых ассетов и просроченных сессий ещё не реализован.

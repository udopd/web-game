# Сетевой режим

Комната поддерживает 1–4 участников. Сервер фиксирует contentVersion при создании, campaignId, server seed и runId при старте. Клиенты получают именно эту версию ресурсов, включая после переподключения. Лидер может передать роль и удалить участника до старта; старт доступен только после ready всех участников. При отключении лидера роль получает подключённый участник.

WebSocket `/ws/rooms/:id` проверяет player cookie и Origin при handshake, затем членство в комнате. Каждые 10 секунд перепроверяется существование/срок сессии. Лимиты: 4096 bytes/message, 90 сообщений/секунду. Клиент отправляет только типизированный input: seq, movement, aim, fire, interact, weaponSlot и необязательные выборы mutation/exit. Дополнительные поля вроде hp отклоняются. Старые seq не применяются.

Симуляция выполняется на сервере с шагом 1/30 секунды; snapshot рассылается раз в два ticks, события — каждый tick. Клиент дедуплицирует eventId и отображает snapshot. Несколько браузеров одного пользователя заменяют предыдущее WS-соединение. Когда все соединения пропали, комната приостанавливается.

Сохранение каждые 150 ticks и при выходе/завершении содержит RNG, сущности и progression. Транзакция считает только ещё не записанную дельту kills/depth и idempotent progress events. Покинувший забег участник получает canResume=false, его actor помечается departed и не возрождается на следующем уровне. Он не получает последующие награды команды. Перезагрузка после завершения восстанавливает экран результата до явного выхода в лагерь.

Проверки: четыре независимых браузера проходят join/ready/start/transfer/reload; четыре сырых WS-клиента получают одинаковые snapshots на одном tick, проходят reconnect и проверку отключения наград. Это не заменяет полный ручной совместный проход кампании или тест плохой сети. Predictive rollback, lag compensation, spectator mode и горизонтальный scaling отсутствуют.

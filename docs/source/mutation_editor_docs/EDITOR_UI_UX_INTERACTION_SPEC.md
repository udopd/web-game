# EDITOR_UI_UX_INTERACTION_SPEC.md

> **Статус: обязательное дополнение к мастер-промпту.** Спецификация UX/UI закрытого браузерного редактора контента 2D pixel roguelike. Этот файл определяет поведение приложения, сценарии взаимодействия, панели, визуальную обратную связь, граф событий и универсальные тестовые сцены. Связан с `LEVEL_AND_CAMPAIGN_EDITOR.md`, `AUDIO_PARTICLES_SETTINGS_PIPELINE.md`, `CHARACTER_ANIMATION_PIPELINE.md` и `EDITOR_SECURITY_AND_ARCHITECTURE.md`.

## 1. Продуктовая цель и критерии качества

Редактор должен ощущаться как **небольшая, быстрая, дружелюбная профессиональная программа**, а не веб-страница с длинными формами. Основной приоритет — выполнять 90% типичных задач через понятные визуальные действия: выбрать объект, увидеть его, поменять параметры, немедленно испытать, проверить ошибки и сохранить.

- Минимализм, аккуратная типографика, спокойная цветовая палитра, четкая иерархия.
- Каждый интерактивный элемент имеет предсказуемые состояния: default, hover, focus-visible, pressed, dragging, drop-valid, drop-invalid, loading, success, error, disabled.
- Критически важные операции имеют визуальное подтверждение, кнопку отмены там, где действие обратимо, и безопасное восстановление после ошибок.
- Не смешивать редактирование контента, его визуальное испытание и публикацию; эти функции представлены отдельными режимами и требуют явных действий.
- Редактор доступен **только** после проверки `ADMIN_EDITOR_TOKEN` на сервере и выдачи защищенной админ-сессии. Ни исходные ассеты-черновики, ни WebSocket предпросмотра, ни экспорт/публикация не должны обходить авторизацию.
- UI должен быть локализуемым (RU/EN), масштабируемым, работать с мышью, клавиатурой, тачем; на узком экране использовать вкладки/слайды вместо крошечных колонок.

## 2. Информационная архитектура

### 2.1. Основные страницы / маршруты

| Маршрут | Раздел | Задача |
|---|---|---|
| `/editor/login` | Админ-вход | Ввод токена, безопасная установка сессии |
| `/editor/projects` | Проекты | Черновики, недавние проекты, версии, import/export |
| `/editor/workspace/:projectId` | Workspace | Единая док-панельная среда для всех объектов |
| `/editor/level/:levelId` | Level Studio | Редактор тайлов, объектов, спавна и валидация |
| `/editor/campaign/:sequenceId` | Campaign Studio | Последовательность уровней/биомов, ветки, боссы и unlocks |
| `/editor/assets` | Asset Library | Спрайты, анимации, музыка, SFX, частички, импорт |
| `/editor/validate/:projectId` | Validation | Ошибки JSON, ссылки, карты, баланс, версии |
| `/editor/settings` | Editor Preferences | Тема, язык, хоткеи, layout, accessibility |

Маршруты — навигационные представления **одного** приложения: смена раздела не должна приводить к утрате несохраненных правок и сбросу открытых панелей. Инструмент открывается либо как dockable вкладка, либо как полноэкранный workspace с сохранением прежнего layout.

### 2.2. Разделение вкладок и сущностей

Первичная навигация: **Content / World / Logic / Assets / Test / Publish**.

- `Content`: Characters, Weapons, Projectiles, Beams, Mutations, Statuses, Enemies, Bosses, Chests, Loot, Props.
- `World`: Tile Palettes, Tilemaps, Room Templates, Level Studio, Biomes, Generation Rules, Campaign/Sequence.
- `Logic`: Event Graph, Conditions, Actions, AI Graph, Camera Effects, Event Bindings.
- `Assets`: Sprite Manager, Animation Studio, Audio Studio, Particle Lab, Asset Browser.
- `Test`: Simulation Scenes, Replays, Profiler, Validation, Debug Overlay.
- `Publish`: Diff, Dependencies, Export ZIP, Version History, Publish.

Каждый объект открывается в собственной вкладке вида `Revolver*`, `Boss: Iron Beast`, `Level 3`. Знак `*` или небольшая точка означает несохраненные изменения; tooltip объясняет состояние. Имеются `Close`, `Close Others`, `Close Saved`, `Pin Tab`, `Copy Reference`, `Reveal in Browser`. Массовое закрытие с несохраненными правками требует безопасной процедуры.

## 3. Панели рабочего пространства и окна

### 3.1. Базовый layout для desktop (например, ≥1280 CSS px)

```text
┌─────────────────────────────────────────────────────────────────────────────────┐
│ PROJECT  ▾ | Content  World  Logic  Assets  Test  Publish | ⌕ | ? | Save | ▶ │
├─────────────┬───────────────────────────────────────────────┬───────────────────┤
│ ASSET TREE  │ [ Revolver ● ] [ Level 01 ] [ Particle Lab ]  │ INSPECTOR         │
│ search ...  ├───────────────────────────────────────────────┤ tabs: Basic/FX/   │
│ Weapons     │                                               │ Advanced          │
│ Projectiles │    PREVIEW / EDITOR CANVAS                    │ damage      [ 8 ] │
│ Characters  │    zoom · pan · grid · overlays                │ spread      [ 2 ] │
│ Enemies     │                                               │ sound   [choose]  │
│ Levels      │                                               │ tooltip / errors  │
├─────────────┴───────────────────────────────────────────────┴───────────────────┤
│ [Event Graph] [Timeline] [Validation] [Console] [Statistics] [Import Queue]     │
├─────────────────────────────────────────────────────────────────────────────────┤
│ READY  ·  Draft saved at 12:30 · 0 errors · 1 warning · Preview 60 FPS       │
└─────────────────────────────────────────────────────────────────────────────────┘
```

Все 4 основных зоны dockable: левый браузер, центр, правый инспектор, нижняя утилитарная панель. Не делать фиксированного расположения, которое нельзя изменить.

### 3.2. Менеджер окон

**Обязательные операции:**

1. Перенос вкладки за drag-handle в другую группу, перестановка, side-dock (left/right/top/bottom), объединение в tab group.
2. **Свободно плавающая панель** внутри окна приложения: перетаскивание, изменение размера, закрепление поверх других окон (`always-on-top` только внутри редактора), свернуть в заголовок, развернуть/restore, закрыть.
3. Максимизация конкретной панели и возврат к предыдущему расположению без потери размеров.
4. Сворачивание боковых областей (sidebar collapse) и нижней панели; клавиатурное раскрытие.
5. Сохранение и восстановление layout по пользователю/проекту/устройству; пресеты `Default`, `Animation`, `Level Design`, `Combat`, `Debug`; `Reset Layout` с подтверждением только при наличии несохраненной персонализации.
6. Сохранение фокуса и редакторского selection после изменения layout.
7. При попытке вынести окно в отдельное окно браузера разрешить только **same-origin** и отдельно авторизованный маршрут; учесть блокировку popup браузером. Базовый рабочий процесс не должен зависеть от popout.
8. Не сохранять секретные токены и чувствительные ответы API в layout JSON.

**Реализация:** базовый кандидат `dockview-react` для докинга/вкладок/флоатинга/сериализации. Компоненты самих редакторов должны быть независимы от dock manager: `EditorPanelRegistry` создает компонент по `panelType` и `entityId`.

Пример сериализуемого состояния высокого уровня:

```json
{
  "schemaVersion": "1.0.0",
  "preset": "level-design",
  "activePanelId": "level:level_wasteland_01",
  "panels": [
    { "id": "level:level_wasteland_01", "type": "level_studio", "entityId": "level_wasteland_01", "pinned": true },
    { "id": "logic:boss_iron", "type": "event_graph", "entityId": "boss_iron", "pinned": false }
  ],
  "dockLayout": {},
  "sidebarCollapsed": false,
  "bottomPanelCollapsed": true
}
```

`dockLayout` — сериализованная структура менеджера окон. Она не включается в экспорт игрового контента; пользовательская настройка рабочего места хранится отдельно.

## 4. Визуальная система (design tokens)

**Тема:** dark-first с полноценной светлой темой. Пример сдержанной палитры (регулируется через tokens): фон `#121A23`, поверхность `#1C2732`, приподнятая поверхность `#283643`, текст `#EAF1F2`, приглушенный текст `#A5B8C3`, акцент `#A5D980` (светло-зеленый), selected-outline `#70C5A2`, error `#E78A90`, warning `#F0C271`. Цвет не является единственным обозначением статуса: использовать иконку/текст.

- Базовый шаг отступов 4 px, стандартные интервалы 8/12/16/24 px.
- Контролы не мельче 36–40 px на desktop, интерактивные цели касания преимущественно 44 px на touch.
- Радиусы 6–12 px, умеренные границы, минимум теней и ненужных градиентов.
- Типографика: системный sans-serif с хорошей кириллицей для форм; monospace только для ID/чисел/JSON.
- Панельные заголовки и действия — всегда в понятных зонах, без непредсказуемого перемещения controls.
- Активная вкладка имеет явный индикатор и читаемое название; длинные названия сокращаются с tooltip.
- Анимация интерфейса 100–180 мс для hover/expand, при `prefers-reduced-motion` transitions минимизируются. Геймплейные покадровые изображения в предпросмотре не должны сглаживаться.
- Не использовать чрезмерные bounce-анимации или постоянные декоративные пульсации.

## 5. Drag-and-drop: микрообратная связь и курсоры

| Ситуация | Курсор и реакция | Визуальная обратная связь |
|---|---|---|
| Наведение на drag-handle | `grab` | Ручка видима, мягкое подсвечивание заголовка |
| Перетаскивание панели | `grabbing` | 1–2 px контрастная обводка окна, ghost-превью и подсвеченная допустимая docking-zone |
| Валидная зона дропа | `copy`/`grabbing` по типу операции | Акцентный outline + полупрозрачная область + подпись «Разместить справа» |
| Недопустимая зона | `not-allowed` | Тонкая красная обводка, подпись с причиной, drop запрещен |
| Перенос ассета в слот | `copy` | Highlight слота, ghost thumbnail и название ресурса |
| Перенос узла графа | `grabbing` | Тень/обводка узла, направляющие, snap-to-grid |
| Изменение размеров панели | `col-resize`, `row-resize`, `nwse-resize` | Highlight разделителя и текущий размер |
| Pan холста | `grab` → `grabbing` | Сдвиг viewport без перемещения объектов |
| Рисование тайлов | `crosshair` | Превью кисти/штампа по сетке |
| Перемещение объектов на карте | `move` | Bounding box, snapping guides, координаты и режим коллизии |
| Связывание портов графа | `crosshair` | Предпросмотр ребра, совместимые порты подсвечиваются |

Применять `pointer capture`, порог начала перетаскивания 4–6 px и явный drag-handle, чтобы пользователь мог выделять текст в инспекторе. На таче — альтернативное меню `Move to panel`, long-press там, где уместно; не блокировать scroll из-за глобального drag handler. Клавиатурные аналоги обязательны хотя бы для открытия/перемещения панелей и перестановки важных элементов.

**Drop outline** — не просто украшение: система должна сообщать, *что произойдет после отпускания*. Нельзя подсвечивать слот как допустимый до успешной проверки MIME/назначения/ID-ссылки.

## 6. Верхняя интерактивная подсказка (Context Help Bar)

Постоянно доступная компактная полоса помощи под основной навигацией; может быть свернута в иконку `?`, но по умолчанию видна для начинающего пользователя.

**Содержимое по выбранному контролу:**

- **Что редактируем:** «Projectile → Collision radius».
- **Что изменится:** «Радиус столкновения снаряда в мировых единицах; влияет на попадания, не меняет размер спрайта».
- **Допустимые значения:** `0.5–64`; единица измерения.
- **Связанные объекты:** переход к `projectileId` или `spriteId` по клику.
- **Пример:** «3 — тонкая пуля, 12 — крупный шар».
- **Предупреждение:** «Повлияет на расчеты серверной симуляции».

Обновляется при `hover`, `focus`, выборе поля, ошибке валидатора или наведении на узел графа. При потере hover сохраняется информация о выделенном поле — без мигания. Tooltip может закрепляться (Pin Help), открывать расширенную справку, использовать клавиатуру `F1`. Источник текстов — типизированный `FieldHelpRegistry` / UI schema; неизвестные поля не остаются без описания. Секреты/значения токенов никогда не выводятся в подсказках.

## 7. Предпросмотры и симуляции: одна оболочка, разные сцены

Создать `SimulationWorkbench` с независимыми `PreviewScene`-адаптерами, переиспользующими игровой рендерер и simulation packages.

### 7.1. Панели превью

| Окно | Что происходит | Обязательные инструменты |
|---|---|---|
| `Character Playground` | Ходьба/бег, aim, idle/hurt/death/victory, масштаб | WASD, speed slider, hitbox, frame-step, reset |
| `Animation Preview` | Отдельный клип со spritesheet | Timeline, FPS/frame-duration, onion skin, pivot, flip |
| `Weapon Range` | Стрельба по манекену и препятствиям | DPS, траектория, collision, reload, slow-motion |
| `Particle Lab` | Эмиттер отдельно от уровня | Spawn trigger, burst, gravity, drag, spin, count, FPS |
| `Audio Preview` | Звук или музыка | Waveform, audition, loop, volume, spatial pan |
| `Chest Simulation` | Открытие и дроп | Open/Reset, десять тестов, preview loot, animation events |
| `Enemy Playground` | ИИ, windup, стрельба, урон, смерть | AI states, target dummy, detect range, forced state |
| `Boss Arena` | Фазы и паттерны | Force HP/phase, replay telegraphs, projectile visualization |
| `Room/Level Preview` | Карта, спавн, разрушаемость, выход | Навигационная сетка, collision, seed, replay |
| `Event Graph Test` | Запуск события и исполнение графа | Trace, breakpoint, event payload, action results |

### 7.2. Общий Toolbar симуляции

`▶ Play / ❚❚ Pause / ▷ Step / ↺ Reset / 0.25×–4× Speed / Seed / Hitboxes / Navmesh / Events / Profiler / Pop-out Preview`.

- **Строго отделить** изолированный sandbox-предпросмотр от настоящего мультиплеерного забега: тестовый запуск не изменяет серверную статистику, сохранения и unlocks.
- Воспроизводимые seed, версии контента и simulation build отображаются сверху окна.
- В preview должны использоваться **текущие изменения черновика** после локальной валидации, а не только опубликованный пакет.
- В preview разрешены быстрые рестарты, hot reload безопасных JSON-параметров и временное изменение HP/time-scale.
- Превью должно показывать состояние `loading`, `ready`, `running`, `paused`, `error`, `stale`; при падении одного preview не должен рушиться весь редактор.
- Звуковой предпросмотр запускается после действия пользователя, если браузер блокирует autoplay.
- Нельзя создавать отдельные несовместимые реализации попаданий/урона ради demo. Игровая логика preview использует общий пакет simulation.

### 7.3. Отображение результата изменений

Редактор различает: `Applied to Preview`, `Saved to Draft`, `Validated`, `Published`. Кнопки и статус-бар не смешивают эти состояния. Пример: изменение `projectile.speed` сразу видно на тестовом полигоне, но публичная игра продолжает использовать старую опубликованную версию до публикации.

## 8. Отдельный визуальный редактор событий и логики

**Event Logic Studio** — отдельная dockable панель и `/editor/workspace/:projectId?tool=event-graph`, доступная из каждого инспектора кнопкой «Открыть граф». Основа UI — `@xyflow/react`; данные для игры хранятся в независимом **семантическом JSON**. Не экспортировать React Flow layout как игровую логику.

### 8.1. Типы узлов

1. Event Source: `enemy.killed`, `weapon.fired`, `chest.opened`, `boss.phase_changed`, `run.level_completed`, `animation.event`, etc.
2. Condition: сравнения значений, теги, расстояние, проценты HP, наличие мутации.
3. Gate: AND/OR/NOT, cooldown, chance, once-per-run, max-per-tick.
4. Action (gameplay): apply-status, heal, modify-stat, spawn-projectile, grant-ammo — только через валидированный серверный SDK.
5. Action (presentation): play SFX, particles, animation, camera shake — через `PresentationEventRouter` и `triggers/event-bindings.json`.
6. Control: последовательность действий, `DelayTicks` для ограниченной очереди будущих событий.

**Не создавать дублирующий runtime для эффектов:** игровой граф компилируется в структуру `EffectEngine` и `MutationExtension` только для доверенных механик; косметический граф компилируется в `event-bindings.json`; AI-граф компилируется в `ai/behaviors.json`. Графические координаты и цвет узлов — только метаданные редактора.

### 8.2. Порты, ребра и валидаторы

- Узлы имеют типизированные входные и выходные порты (`event`, `boolean`, `entityRef`, `number`, `position`, `action`).
- При перетаскивании соединения совместимые порты светятся, несовместимые объясняются tooltip и не принимают ребро.
- Для игровых цепочек запрещать недекларированные циклы; поддерживаемые delay/loop требуют явного ограничителя, лимита глубины и количества событий за tick.
- Редактор сразу проверяет доступные поля payload для выбранного типа события.
- Для `run.level_completed` требуется гарантированное серверное происхождение — нельзя выдавать unlock по клиентскому `play_animation`.
- Каждый граф имеет `graphId`, `schemaVersion`, версию, перечень входов, список узлов/связей и набор unit-test cases.

### 8.3. Тестирование графа

Пользователь выбирает `Simulate Event` → вводит типизированный payload → наблюдает подсвечивание посещаемых ребер и историю исполнения. Debug trace должен показывать: condition pass/fail, cooldown, chance outcome с seed, найденные действия, причины отказа. Никаких side-effect на реальные профили при тестах.

Пример семантического косметического правила, экспортируемого в существующий `triggers/event-bindings.json`:

```json
{
  "id": "binding_chest_rare_open",
  "event": "chest.opened",
  "conditions": [
    { "field": "rarity", "operator": "eq", "value": "rare" }
  ],
  "actions": [
    { "type": "play_sfx", "soundId": "sfx_chest_rare", "anchor": "event_position" },
    { "type": "spawn_particles", "particleEffectId": "vfx_chest_sparks", "anchor": "event_position" },
    { "type": "camera_effect", "cameraEffectId": "camera_shake_chest", "scope": "local_actor" }
  ],
  "cooldownMs": 0,
  "probability": 1,
  "enabled": true
}
```

## 9. Drag-and-drop загрузка файлов: ощущение качественного приложения

Переиспользовать `AssetDropzone` и `AssetImportQueue` из `AUDIO_PARTICLES_SETTINGS_PIPELINE.md`, но усилить UX:

1. При перетаскивании файлов над редактором появляется **полупрозрачная рамка по периметру рабочей области** с текстом «Отпустите файлы для загрузки»; под целевым контролом — более точное предложение «Добавить кадры в Run» / «Заменить спрайт».
2. Принимаемые типы подсказываются **до отпускания**: PNG, WebP, OGG, WAV, JSON, ZIP (контекстно).
3. Если файлов много, показывать **сначала очередь и план действий**, например «12 PNG → новая последовательность кадров»; не смешивать импорт архива с импортом спрайтов без подтверждения.
4. Каждая строка очереди: thumbnail/icon, название, размер, формат, стадия, процент, скорость по возможности, retry, cancel, ошибки, hash/dedupe.
5. **Отдельные стадии прогресса:** `Uploading`, `Verifying`, `Decoding`, `Generating previews`, `Linking`, `Completed`; процент загрузки сети не равен проценту всей операции. Если серверный прогресс обработки неизвестен, показывать индикатор неопределенной длительности и четкое название стадии, не ложные `100%`.
6. После импорта мягкая зеленая рамка слота и короткий toast `Добавлено: 8 кадров`, ссылка `Открыть последовательность`; при ошибке — красная рамка, конкретная причина и исправление.
7. Поддержать повторные попытки, отмену, отказ от замены используемого ассета, версии, пакетную обработку, SHA-256 и безопасную серверную проверку.
8. На таче drag-drop может быть недоступен — кнопка `Добавить файлы` полностью функциональна; поддерживать системный file picker.

Для загрузки гигабайтовых архивов не требовать обязательной поддержки в первой версии: значения лимитов должны быть документированы; chunked/resumable backend включается только после реализации и тестирования. Никогда не заявлять поддержку resume без реального сохранения upload-сессии на сервере.

## 10. Состояния приложения, обратная связь и сохранения

- Изменения форм debounced для preview; черновик сохраняется атомарно на сервер с revision/ETag и обнаружением конфликтов.
- `Undo/Redo`: команды с reversible patches, bounded history, отдельная транзакция для пакетного drag-paint; пользователь не должен отменять каждый тайл отдельно.
- Сигналы в статус-баре: `Unsaved`, `Saving…`, `Saved`, `Conflict`, `Invalid`, `Offline`, `Publishing…`, `Published`.
- `Ctrl/Cmd+S` сохраняет черновик; `Ctrl/Cmd+Z/Y` — Undo/Redo; `Ctrl/Cmd+P` — command palette; `Space+drag` — pan холста; `F` — focus selected; `Delete` — удалить выделение с возможностью Undo; `Esc` — отмена drag/edge creation/modal.
- Явная отмена операции для необратимых действий (удалить опубликованную версию, сбросить шаблон, очистить библиотеку) с перечислением затронутых объектов.
- Для `Save`/`Export`/`Publish` показывать разные кнопки и разные состояния. Публикация — отдельный wizard `Validate → Diff → Version → Confirm → Publish`.
- Ошибка должна содержать контекст: `world/levels.json → level_forest_02 → exitRef → target level missing` и кнопку `Перейти к проблеме`.
- Не блокировать редактирование всего редактора из-за долгой загрузки одного ресурса.

## 11. Accessibility и mobile-first (не упрощать до неработоспособности)

- WCAG 2.2 AA как целевой уровень: контраст, видимый focus, роль и название у элементов, корректный tab order, keyboard navigation, уведомление ошибок через `aria-live`.
- Tooltip по hover обязательно открывается также по focus; в нем не должно быть критической информации, недоступной клавиатуре/тачу.
- Полноценные тач-сценарии для выбора тайла, прокрутки панелей, настроек спрайта. Точный pixel painting на мобильном можно оформить как отдельный увеличенный fullscreen режим.
- На узких экранах переключаемые панели (Browser / Canvas / Inspector / Tools), но выбранный объект и незаписанные изменения сохраняются.
- Уменьшенное движение, регулировка UI scale, zoom 80–150%, отказ от только цветовых ошибок.

## 12. Рекомендуемые библиотеки и границы

- `React + TypeScript + Vite`: приложения редактора.
- `dockview-react`: docking/tab groups, floating panels, maximize, optional popout, layout serialization; кандидат, подтвердить лицензию/совместимость версии в lockfile.
- `@xyflow/react`: визуальные графы и drag-to-connect; **не runtime графа**.
- `@dnd-kit/*`: элементы библиотек, списки, reordering и доступный drag-and-drop; не нужно применять поверх dock manager там, где drag уже встроен.
- `Phaser 3`: предпросмотр с тем же render/system bridge, что и игра; **изолированный** sandbox симуляции.
- `Zustand` / command store с патчами: editing session и undo/redo; `TanStack Query` для запросов серверной части.
- `Zod` или JSON Schema UI type generation только как вспомогательный слой форм; контракт опубликованного контента — **JSON Schema + Ajv** с едиными типами.
- `Playwright` для E2E взаимодействий с окнами, загрузками, графами, keyboard navigation.

Не вводить одновременно несколько state stores без явной зоны ответственности. Dock layout, контент-пак, симуляция и UI-only selection — **разные данные**.

## 13. Definition of Done — UX тесты

- [ ] Можно открыть три разных объекта во вкладках, переставить их, вынести панель поверх workspace, свернуть, максимизировать и вернуть назад без потери редакторских данных.
- [ ] При drag окна подсвечиваются допустимые docking-зоны; недопустимые зоны объясняются. Курсоры соответствуют действию.
- [ ] После refresh восстанавливается layout, активные вкладки и selection, исключая секреты.
- [ ] `Context Help Bar` показывает смысл, единицу, допустимый диапазон и ссылку на документацию для ключевых полей.
- [ ] Можно создать событие `chest.opened`, связать Condition → SFX → Particles → Camera Shake, проверить и испытать граф.
- [ ] Preview звука, частиц, оружия, анимации персонажа, бега, AI врага и открытия сундука работают независимо от публичной игры.
- [ ] При массовом drag-and-drop корректно отображаются стадии upload/verify/decode/link; отмена и retry работают.
- [ ] `Save`, `Validate`, `Export`, `Publish` действительно выполняют разные операции и имеют честную обратную связь.
- [ ] Переключение узкой/широкой верстки сохраняет выбранный объект и несохраненные изменения.
- [ ] UI не предоставляет неавторизованный доступ к черновикам, ассетам или публикации.
- [ ] Все критические операции доступны с клавиатуры; при reduced-motion не возникает навязчивой анимации.

## 14. Инструкция для ИИ-разработчика

Сначала реализуй `EditorShell`, `PanelRegistry`, `DockLayoutPersistence` и `DesignTokens`. Затем универсальные `AssetBrowser`, `EntityInspector`, `ContextHelpBar`, `SimulationWorkbench`, `EventGraphStudio` и `AssetImportQueue`. После этого подключай редакторы оружия, мутаций, анимаций и уровней через одну систему окон. Для каждого нового инструмента обязательны: панель → inspectors → превью → Help registry → validator → import/export → тест.

**Не считать панель реализованной, если она лишь отрисована.** Проверить реальное изменение данных, undo/redo, сохранение, обработку ошибок, восстановление layout и работу preview.

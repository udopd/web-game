# CHARACTER_ANIMATION_PIPELINE.md

> Дополнение к MASTER PROMPT. **Обязательное требование:** через закрытый `/editor` администратор должен создавать и настраивать покадровые анимации игровых персонажей из последовательностей изображений, без изменения исходного кода игры. Этот документ — контракт для ИИ-разработчика и критерии приемки.

## 1. Что нужно реализовать

Создать в редакторе разделы **Sprite Library → Animation Studio → Character Animation Mapping**. Игровой клиент автоматически загружает анимации из опубликованного JSON-контент-пака при запуске. Администратор может загрузить отдельные PNG/WebP-кадры, spritesheet или atlas, выбрать порядок кадров, длительность, точку привязки и визуально проверить результат.

Обязательные **пять состояний** любого игрового персонажа:

| State ID | Интерфейс | Зациклено? | Переход и смысл |
|---|---|---|---|
| `idle` | Покой | Да | Нет ввода движения и нет блокирующего состояния |
| `run` | Бег | Да | Есть фактическое перемещение выше порога скорости |
| `hurt` | Получение урона | Нет | Сервер подтвердил получение урона; краткая реакция |
| `death` | Смерть | Нет | HP достигло нуля; воспроизвести один раз, зафиксировать последний кадр |
| `victory` | Победа | Нет | Сервер подтвердил завершение уровня/забега; воспроизвести один раз |

Эти клипы обязательны и должны валидироваться перед публикацией. Другие состояния (`attack`, `reload`, `dodge`, `spawn`, `revive`, `stunned`, `interact`) можно добавить впоследствии без переработки движка. `hurt` — не источник нанесения урона, а реакция на авторитетное событие; анимации **не изменяют здоровье** самостоятельно.

## 2. Интерфейс Animation Studio

**Левая панель:** список персонажей, спрайтов, клипов и состояний; поиск, копирование, переименование, создание клипа.

**Центр:** прозрачный checkerboard, zoom 1×/2×/4×/8× (nearest-neighbor), предпросмотр персонажа, наложение pivot, опционально коллайдера и отметок `footPoint`; режимы фон/арена/камера. Кнопки Play, Pause, Stop, Previous/Next Frame, Loop preview, Speed (0.25×…2×). Предпросмотр должен одинаково работать со спрайт-листом и атласом.

**Нижняя панель:** timeline со строго упорядоченными кадрами. Для каждого кадра — миниатюра, длительность в миллисекундах, событие и смещение изображения. Drag-and-drop для перестановки, добавление/удаление/дублирование, выделение группы кадров, импорт серии `run_000.png`, `run_001.png` с естественной сортировкой по числам.

**Правая панель:** инспектор клипа (`id`, `state`, `frames[]`, `loop`, `defaultFrameDurationMs`, `playbackSpeed`, `holdLastFrame`, `origin`, `direction`, `tags`, `events`). Отдельно инспектор кадра (`spriteId`, `durationMs`, `offset`, `events`). Автоматическая пересборка preview при изменении любых параметров.

**Инструменты:** undo/redo, копирование клипов, зеркалирование, пакетное применение pivot, onion skin для предыдущего/следующего кадра, проверка выравнивания стоп и диагностика скачков кадра.

## 3. Файлы и ответственность

- `visuals/sprites.json` описывает *кадры изображений* (`spriteId → source + rectangle + pivot`). Один файл изображения может содержать один кадр или целый атлас.
- `visuals/animations.json` описывает *клипы* (упорядоченные ссылки на `spriteId`, длительности, режим повтора и визуальные события). Нельзя дублировать пути PNG в клипах.
- `entities/characters.json` описывает *персонажей* и `animationSet`: соответствие пяти игровых состояний `animationId`.
- `assets/sprites/characters/...` содержит реальные PNG/WebP файлы, упакованные в ZIP.
- `manifest.json` перечисляет ресурсы и SHA-256, а не логику анимационных переходов.

Обязательное соглашение: идентификаторы строковые, стабильные; пути относительны корню контент-пака. Использовать `schemaVersion: "1.0.0"`; создать соответствующие JSON Schema c `additionalProperties: false`, явными типами и диапазонами.

### 3.1. Пример `visuals/sprites.json`

```json
{
  "schemaVersion": "1.0.0",
  "items": [
    {
      "id": "sprite_hero_idle_00",
      "source": "assets/sprites/characters/hero/idle_00.png",
      "frame": { "x": 0, "y": 0, "width": 32, "height": 32 },
      "pivot": { "x": 16, "y": 28 },
      "renderScale": 1,
      "rotationOffsetDeg": 0,
      "layer": "characters"
    },
    {
      "id": "sprite_hero_idle_01",
      "source": "assets/sprites/characters/hero/idle_01.png",
      "frame": { "x": 0, "y": 0, "width": 32, "height": 32 },
      "pivot": { "x": 16, "y": 28 },
      "renderScale": 1,
      "rotationOffsetDeg": 0,
      "layer": "characters"
    }
  ]
}
```

Другие спрайты в полном пакете задаются аналогично. Поворот, flip и pivot не должны приводить к изменению физической точки коллизии.

### 3.2. Пример `visuals/animations.json`

```json
{
  "schemaVersion": "1.0.0",
  "items": [
    {
      "id": "anim_hero_idle",
      "loop": true,
      "holdLastFrame": false,
      "defaultFrameDurationMs": 150,
      "frames": [
        { "spriteId": "sprite_hero_idle_00", "durationMs": 150, "offset": { "x": 0, "y": 0 }, "events": [] },
        { "spriteId": "sprite_hero_idle_01", "durationMs": 150, "offset": { "x": 0, "y": 0 }, "events": [] }
      ]
    }
  ]
}
```

**Важно:** пример показывает один клип; полный персонаж обязательно имеет все пять клипов. `durationMs` одного кадра — целое положительное число (рекомендуемый диапазон 16…5000). Применять кадры по их явному порядку в массиве; не полагаться на имена файлов при воспроизведении. Если добавятся VFX-события кадров, принимать только ограниченный список *визуальных* событий, без `eval` и без урона/спавна игрового объекта из клиентской анимации.

### 3.3. Пример фрагмента `entities/characters.json`

```json
{
  "id": "character_hero",
  "animationSet": {
    "idle": "anim_hero_idle",
    "run": "anim_hero_run",
    "hurt": "anim_hero_hurt",
    "death": "anim_hero_death",
    "victory": "anim_hero_victory"
  },
  "facingMode": "horizontal_flip",
  "defaultFacing": "right"
}
```

Это **фрагмент объекта персонажа**, не самостоятельный `characters.json`: его нужно включить в `items[]` вместе со всеми обязательными полями персонажа (`stats`, `startingWeaponIds`, `animations` и другими согласно схеме проекта). В актуальной схеме выбрать одно каноническое имя для привязки — **`animationSet`**, а старое `animations` мигрировать/поддержать конвертером, чтобы избежать двух источников истины.

Для минимального проекта достаточно двух направлений (право + horizontal flip для лево). Архитектура должна поддерживать отдельные направления `up`, `down`, `left`, `right`, если контент включает такие наборы кадров. При отсутствии направления должна работать документированная политика fallback без неверной ссылки или пустого кадра.

## 4. State machine игрового персонажа

В клиенте создать универсальный `CharacterAnimationController`. Он получает `character.animationSet`, сведения о текущем состоянии из симуляции, скорость и направление, выбирает анимацию и управляет временной шкалой. Код **не должен проверять конкретный `characterId`**.

Приоритет состояний: `death` (терминальное) → `victory` (если персонаж жив и сервер подтвердил победу) → `hurt` → `run` → `idle`. Статусы `stunned`, `attack` и другие — расширения через отдельные слои/приоритеты после проектирования конфликтов. `hurt` не должен навсегда блокировать движение, если клип проигран.

- Смена `idle ↔ run` без перезапуска клипа каждый кадр.
- При повторном событии получения урона `hurt` может стартовать заново по явно заданному правилу.
- При смерти немедленно остановить циклический клип, воспроизвести `death` однократно, сохранить последний кадр.
- При победе воспроизвести `victory` однократно; не начинать повторно каждый игровой тик.
- При переходе на другой уровень сбросить victory-состояние после завершения перехода.
- В кооперативе все клиенты отображают подтвержденные сервером состояния; **не** отправлять кадровую анимацию по сети. Синхронизировать игровые события/состояния и при необходимости время входа в них, визуальное воспроизведение делать локально.
- Параметр `facingMode` (`horizontal_flip`/`directional`) задает направление, не меняя коллизию. Слои оружия и тела могут анимироваться независимо.

## 5. Формат и события

Данные клипов должны оставаться презентационными. `onHit`, `applyDamage`, `spawnProjectile` и прочие авторитетные игровые события исполняются только системой симуляции, а **не при достижении кадра** на клиенте. Если требуется привязка удара к конкретному кадру, серверная симуляция использует отдельную типизированную шкалу атаки в combat-данных; клиент лишь визуализирует соответствующую фазу. Это важно для честного мультиплеера и детерминированных реплеев.

Для пользовательских эффектов допускаются только безопасные визуальные event types: `play_visual_effect`, `play_local_sound`, `camera_shake_local`, `spawn_cosmetic_particle` с валидируемыми параметрами. Визуальные события могут быть пропущены в зависимости от производительности и не влияют на результат боя.

## 6. Пайплайн через редактор

1. Администратор проходит авторизацию `/editor/login` по защищенному токену из серверного `.env`. Все API кадров и ресурсы приватных черновиков требуют админ-сессии.
2. В Sprite Library загрузить PNG/WebP кадры или spritesheet.
3. При нарезке sheet задать сетку (ширина/высота), поля, отступы и начальный номер; система создаст записи в `sprites.json`.
4. В Animation Studio выбрать персонажа и `idle`; добавить последовательность кадров; настроить FPS/длительности, loop, pivot, offsets; проверить анимацию.
5. Повторить для `run`, `hurt`, `death`, `victory`. Редактор показывает контрольный список «5/5 анимаций».
6. В Character Animation Mapping назначить клипы соответствующим состояниям, выбрать политику направления/зеркалирования.
7. Запустить тестовую арену: движение, получение урона, смерть и победа должны переключать клипы автоматически. Предусмотреть кнопки **Simulate Damage**, **Simulate Death**, **Simulate Victory**, **Reset** — только для предпросмотра.
8. Запустить валидатор: `animationId` существуют, последовательность непуста, spriteId разрешимы, PNG читаются, frame rect в пределах изображения, durations > 0, все пять состояний назначены.
9. Сохранить черновик. Выполнить экспорт ZIP и повторный импорт. Необходимо сохранить порядок кадров, pivot, скорость воспроизведения, loop и ссылки.
10. Опубликовать новую неизменяемую версию. Клиент автоматически загрузит анимации с новым контент-паком при создании нового забега; текущие забеги остаются закреплены за прежней версией.

## 7. Обязательные тесты

- Unit: выбор `idle/run/hurt/death/victory`; правильный приоритет; клип не перезапускается на каждом тике; одноразовые клипы завершаются; правильный flip.
- Validation: отсутствующий клип, пустой frames[], 0 ms, кадр вне границ атласа, неизвестный `spriteId`, дублированный ID.
- UI/E2E: загрузить 5 серий кадров, собрать клипы, переназначить через инспектор, увидеть предпросмотр, применить Undo, экспортировать/импортировать и получить идентичную последовательность.
- Multiplayer: 2 клиента видят смерть игрока, победный клип не запускается до подтверждения сервера, кадры не влияют на урон.
- Performance: кешировать атласы и клипы, освобождать текстуры по референсам, ограничивать размер импорта; не пересоздавать спрайтовые текстуры на каждом render tick.
- Accessibility/UX: на узком экране timeline и inspector доступны вкладками, управление кнопками подписано; кнопки Pause/Frame navigation доступны с клавиатуры.

## 8. Критерии приемки (Definition of Done)

- [ ] В закрытом редакторе можно загрузить набор отдельных файлов PNG/WebP как кадры.
- [ ] Можно нарезать spritesheet на кадры и назначить их анимации.
- [ ] Для каждого персонажа созданы/назначены `idle`, `run`, `hurt`, `death`, `victory`.
- [ ] Есть timeline с сортировкой drag-and-drop, длительностью каждого кадра и проигрыванием в реальном времени.
- [ ] Можно настроить loop, однократное проигрывание, закрепление последнего кадра, масштаб и pivot.
- [ ] Тестовая арена переключает состояния по реальным событиям симуляции.
- [ ] Данные записываются в `sprites.json`, `animations.json`, `characters.json`, включаются в экспорт ZIP и автоматически загружаются игрой.
- [ ] Отсутствующая обязательная анимация блокирует публикацию с понятной ошибкой.
- [ ] Импорт экспортированного архива восстанавливает последовательность и параметры без потерь.
- [ ] Мультиплеер не синхронизирует отдельные кадры, не доверяет визуальным событиям и правильно отображает смерть/победу.
- [ ] Закрытый редактор и его черновые ассеты доступны только авторизованному администратору.

## 9. Инструкция ИИ-разработчику

Добавь систему анимации персонажей по описанной архитектуре. Сначала сделай `sprites.json`/`animations.json`/`characters.json` и JSON Schema, затем import/spritesheet slicing, визуальный timeline, превью на Phaser, универсальный state controller, интеграцию в игру, тесты и round-trip export/import. Сохрани совместимость с уже определенными JSON-структурами и применяй миграцию, если старые объекты содержат поле `animations`. Не реализуй отладочные кнопки как боевые команды реального клиента. Не встраивай PNG в JSON как base64; храни файлы в assets и используй ID-ссылки. Не привязывай боевую логику к клиентским кадрам.


## 10. Связь Animation Studio с независимыми SFX/VFX-модулями

Полное описание: [`AUDIO_PARTICLES_SETTINGS_PIPELINE.md`](./AUDIO_PARTICLES_SETTINGS_PIPELINE.md).

- В timeline каждого кадра добавить **SFX events** (`soundId`), **Particle events** (`particleEffectId`) и **Camera effects** (`cameraEffectId`) с выбором по ID из общих библиотек редактора.
- Действия `play_local_sound`, `spawn_cosmetic_particle`, `camera_shake_local` **не исполняются AnimationController самостоятельно**, а передаются в `PresentationEventRouter`; к логике попаданий/урона кадры анимаций не привязывать.
- При проигрывании `idle`, `run`, `hurt`, `death`, `victory` допустимы собственные звуки и частицы; последовательность кадров и их события экспортируются в `animations.json`, ссылки остаются проверяемыми.
- Временно зацикленные эффекты прекращаются при переходе в другое состояние, удалении персонажа или выгрузке сцены.
- PNG/WebP последовательности, spritesheets, аудио и связанные ассеты загружаются единым `AssetDropzone` с drag-and-drop, прогрессом, отменой, обработкой дубликатов и fallback-кнопкой выбора файлов.
- Проверить на персонаже все пять анимаций с SFX и частицами; авторитетная симуляция не зависит от того, были ли эффекты реально воспроизведены.


## 11. Анимации врагов и боссов: необязательная подготовка атаки

Пайплайн врагов и боссов описан в [`WORLD_CONTENT_AND_UNLOCKS_PIPELINE.md`](./WORLD_CONTENT_AND_UNLOCKS_PIPELINE.md). `Animation Studio` переиспользуется без дублирования кода; размеры (спрайт/scale) и физические коллайдеры задаются независимо. Для врагов и боссов поддержать `idle`, `run`, `hurt`, `death`, опциональные `attack`, `windup` и клипы смены фаз. **Пять обязательных клипов игрового персонажа (`idle/run/hurt/death/victory`) не становятся автоматически обязательными для врагов.**

- `windup` назначается в `animationSet` по ID (либо отсутствует). `windupMs` живет в боевой шкале `combat/attack-patterns.json`/attack config и не берется из длительности кадров.
- При серверном `enemy.attack_windup_started`/`boss.attack_windup_started` проиграть `windup` с заданной политикой растяжения/зацикливания/удержания кадра. При отсутствии анимации — телеграфный визуальный fallback, не отказ атаки.
- При `attack_cancelled` остановить клип и косметические таймеры; при `attack_executed` переключиться на подходящее состояние. Истина о выстреле/уроне — только на сервере.
- При фазовом переходе босса могут смениться animationSet/palette/scale, но hitbox и физические свойства должны изменяться только при явной серверной команде из типизированной боевой конфигурации.
- События кадров допустимы только косметические и исполняются единым PresentationEventRouter.

## 12. Обновление интерфейса Animation Studio и отдельное ТЗ для ИИ-графики

- `Animation Studio` должна открываться в dockable/tabbed workspace с независимым timeline, предпросмотром в `SimulationWorkbench` и `ContextHelpBar` для frame duration, loop, pivot, события, коллизии и направления; базовые UX-правила — `EDITOR_UI_UX_INTERACTION_SPEC.md`.
- Поддержать batch drag-and-drop нескольких PNG с предпросмотром последовательности, сортировкой файлов по `frameIndex`, ручной перестановкой, dedupe, прогрессом, отменой, ошибками формата/размера, Undo/Redo.
- `AI_PIXEL_ART_GENERATION_GUIDE.md` — самостоятельная инструкция графической модели для генерации стабильных кадров idle/run/hurt/death/victory, optional windup/attack, разного размера персонажей/врагов/боссов, consistent pivot/canvas/palette и названий PNG. Никакой автоматической смены поведения игры от самой картинки.
- Превью должно одновременно показывать `actual pixels`, zoomed pixels, hitbox, точку опоры, event markers и `onion skin`; быстрый запуск пяти обязательных состояний доступен без открытия реального игрового забега.
